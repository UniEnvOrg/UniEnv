    Bases: BatchBase[BatchT, BArrayType, BDeviceType, BDtypeType, BRNGType]

    Ring-buffer style batch storage built on top of a SpaceStorage.

    The buffer exposes the standard BatchBase interface while handling round-robin overwrite semantics, persistence metadata, and optional multiprocessing-safe counters.

    With multiprocessing=True writers serialize on a shared lock and publish count and offset together; readers in other processes take no lock and always map indices with a consistent pair. A read that races with a write can still return rows that the write is overwriting (the oldest samples of a full buffer), as with any lock-free ring buffer.

    Wrap a storage object with replay-buffer indexing semantics.

    episode_buffer holds the episode records of the segments (see create); step_episode_ids maps every storage slot to the episode of the step it holds (-1: no closed episode) and next_episode_id is the id of the next record.

    multiprocessing: bool = False,
    maintain_segment_metadata: bool = False,
    episode_space: Optional[Space] = None,
    episode_storage_cls: Optional[Type[SpaceStorage]] = None,
    episode_capacity: Optional[int] = -1,
    episode_storage_kwargs: Optional[Dict[str, Any]] = None,
    **kwargs,
) -> ReplayBuffer[BatchT, BArrayType, BDeviceType, BDtypeType, BRNGType]

    Create a new replay buffer and its backing storage.

    With episode_space, every segment (episode) of the buffer carries one record of that space (task, instruction, success, return, ...), stored once in a second storage of episode_storage_cls (episode_storage_kwargs) and passed when the segment closes (extend(..., episode_data=...), mark_segment_end(episode_data=...), commit_segment(writer, episode_data=...)): every segment requires one. Records are kept for as long as any step of their episode is in the buffer; episode_capacity (-1: the buffer's capacity, which always suffices) bounds how many are stored. Segment metadata is maintained. See :meth:get_episode_data and :meth:with_episode_data.

This avoids allocating duplicate Space objects when many buffers with identical spaces are loaded simultaneously (e.g. for CombinedBatch).

    open_segment_writer ¶

    open_segment_writer() -> SegmentWriter

    A writer that builds one segment off to the side; commit_segment() then appends it at the tail. Unlike append() / mark_segment_end(), any number of writers can be open at a time (e.g. one per environment of a batched rollout), and they can be committed in any order. Storages that support it (e.g. VideoStorage) encode the samples as they are appended.

    commit_segment ¶

    commit_segment(writer: SegmentWriter, *, episode_data: Optional[Any] = None) -> None

    Append the segment built by writer (from open_segment_writer()) at the tail, as extend() would.

    episode_data is the segment's episode record (required if the buffer has an episode_space; an empty writer is aborted and needs none).

    get_episode_data ¶

    get_episode_data(episode_ids: Union[int, Sequence[int], ndarray]) -> Any

    The episode record of each id (one record for an int, a batch for an array).

    The episodes available are the ones with a step in the buffer. Raises IndexError for -1 (a step of the open segment), for episodes whose steps were all overwritten (or whose record no longer fits episode_capacity) and for unknown ids.

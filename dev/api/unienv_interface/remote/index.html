    unienv_interface.remote¶

    Lightweight RPC for UniEnv environments, worlds, nodes, data transformations and policies.

    Host objects with :class:RemoteServer and use them through :class:RemoteClient proxies that implement the normal Env / World / WorldNode / DataTransformation / Policy interfaces. Transports: TCP, Unix sockets, WebSocket (optional websockets dependency) and in-memory. See docs/guides/remote-execution.md.

    Modules:

    Name Description
    client

    Connect to a :class:RemoteServer and call hosted objects.
    compression

    Opt-in lossy compression of server-to-client image arrays.
    errors

    Errors raised by the remote client.
    protocol

    Protocol constants shared by client and server.
    proxies

    Local Env / World / WorldNode / DataTransformation / Policy views of objects hosted by a server.
    server

    Host environments, worlds, nodes, data transformations and policies for remote clients.
    transport

    Frame transports: TCP and Unix stream sockets, WebSocket, and in-memory pairs.
    wire

    Safe wire format: one JSON document plus raw binary attachments. No pickle.

    RemoteClient ¶

    RemoteClient(
    transport: Transport,
    *,
    backend: ComputeBackend = NumpyComputeBackend,
    device: Optional[Any] = None,
    timeout: Optional[float] = None,
    compress: Optional[Dict[str, str]] = None,
)

    A connection to a :class:RemoteServer. Thread-safe: calls may be concurrent.

    Results are converted to backend arrays on device. A remote exception is re-raised as :class:RemoteError; a lost connection raises ConnectionError, in which case a call that was in flight may or may not have run on the server. timeout (seconds, None = wait forever) bounds each call; a timed-out call keeps running on the server.

    Objects the server hosts through register_factory are opened (built on the server if needed) the first time this client gets their proxy or calls them, and released by :meth:release, close() on their proxy, or closing the client.

    RemoteDataTransformation ¶

    RemoteDataTransformation(client: RemoteClient, name: str)

    Bases: _Remote, DataTransformation

    A DataTransformation hosted by a :class:RemoteServer.

    transform and get_target_space_from_source run on the server: the source space and the data are rebuilt there on the backend / device the transformation was registered with, and the result comes back on the client's. Use it to run a transformation whose dependencies live in another environment (e.g. a grasp synthesizer pinned to an old CUDA toolchain).

    The proxy has no inverse and cannot be serialized: it is bound to its connection (serialize the hosted transformation on the server instead).

    RemotePolicy ¶

    RemotePolicy(client: RemoteClient, name: str)

    Bases: _Remote, Policy

    A Policy hosted by a :class:RemoteServer.

    reset, observe_transition, get_action and visualize_action run on the server, so the policy's state lives there: the context and observations sent are rebuilt on the hosted policy's backend / device, and actions come back on the client's. Use it to run a policy on another machine (a GPU server for a robot) or in another environment (pinned dependencies). Spaces and batch_size are the hosted policy's.

    RemoteServer ¶

    RemoteServer(
    *,
    max_frame_size: int = DEFAULT_MAX_FRAME_SIZE,
    send_timeout: Optional[float] = 60.0,
)

    Serve registered objects to :class:RemoteClient connections.

    Example::

    with RemoteServer() as server:
    server.register("sim", env)  # or register_recursive() to also host its world and nodes
    server.serve("tcp://0.0.0.0:7000")  # blocks; or listen() in the background

    Each registered root runs on its own worker thread, shared by every hosted object with the same world; calls on them are executed there one at a time, in arrival order, whichever client sent them. Only the methods in protocol.METHODS can be called. :meth:register_factory hosts an object that is built when a client first opens it and closed once no client uses it.

    Replies are sent from the worker, so a client that stops reading would stall every client of that worker: a connection whose send makes no progress for send_timeout seconds is closed (TCP and Unix sockets; None waits forever).

    Methods:

    Name Description
    register

    Host obj (an Env, World, WorldNode, DataTransformation or Policy) under name.
    register_recursive

    Like :meth:register, but also expose everything obj is built from.
    register_factory

    Host the object factory() builds, only while clients use it.
    listen

    Accept connections on address in the background; return the bound address.
    serve

    Listen on address and block until :meth:close (or Ctrl-C).
    connect

    An in-process client over a :class:MemoryTransport (mainly for tests).
    publish

    Send value to the subscribers of hosted env name as the result of method.
    close

    Stop listening, drop every connection, close owned objects on their workers.

    register ¶

    register(
    name: str,
    obj: Hosted,
    *,
    close: bool = True,
    backend: Optional[ComputeBackend] = None,
    device: Optional[Any] = None,
    publish_results: bool = True,
) -> str

    Host obj (an Env, World, WorldNode, DataTransformation or Policy) under name.

    Only obj itself is exposed; use :meth:register_recursive to also expose the world and nodes it is built from. Objects sharing a world (e.g. an env and its world registered separately) run on the same worker. Registering an object that is already hosted returns its existing name. With close=True the server closes obj (on its worker) when it shuts down.

    A Policy runs on its own worker like an env; the observations and contexts a client sends are rebuilt on the policy's backend / device. Host a FuncPolicy as FuncPolicyBasedPolicy(func_policy).

    A DataTransformation has no backend of its own: backend / device (default: numpy, no device) are where the source spaces and data of its calls are rebuilt on the server. Other objects use their own.

    register_recursive ¶

    register_recursive(name: str, obj: Hosted, *, close: bool = True) -> str

    Like :meth:register, but also expose everything obj is built from.

    An env built on a WorldEnv also exposes name/world and name/node (the root node), and every node exposes its world (<node name>/world, unless already hosted) and its children as <node name>/<child>, so clients can compose them in components mode. Objects already hosted keep their first name.

    register_factory ¶

    register_factory(
    name: str,
    factory: Callable[[], Hosted],
    *,
    release_after: Optional[float] = 60.0,
    backend: Optional[ComputeBackend] = None,
    device: Optional[Any] = None,
) -> str

    Host the object factory() builds, only while clients use it.

    The object is built on its own worker thread when a client first opens name (client.env(name), client.resource(name), ...; its spaces and attributes are read then), and closed there release_after seconds after the last client that opened it disconnects or calls close() on its proxy (0: at once, None: never). The next client gets a newly built object, which it resets first like any fresh env. backend / device are given for a factory of DataTransformation s, as in :meth:register. Only the object itself is hosted (no :meth:register_recursive counterpart).

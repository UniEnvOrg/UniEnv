    Abstract description of a valid data domain.

    Spaces carry backend, device, shape, and dtype metadata and define the operations needed by the rest of UniEnv: validation, sampling, empty value creation, serialization-friendly representation, and backend/device conversion for both the space definition and its data.

    In-place changes to a space (reassigning one of its attributes, or e.g. DictSpace.__setitem__) increment the global Space._mutation_epoch. Caches keyed on a space's identity (e.g. in ChainedTransformation) include this counter, so mutating a space can never make them stale. BoxSpace is immutable after construction and is not tracked.

    Metadata¶

    Every space carries an optional, read-only metadata mapping (constructor keyword metadata=) describing what its data means, e.g. BoxSpace(..., shape=(480, 640, 3), metadata={"kind": "image", "format": "rgb"}). Values must be JSON-serializable; they are validated and deep-copied at construction and exposed as a :class:SpaceMetadata (empty when absent). Nested spaces carry their own metadata, so every camera of a DictSpace observation can be described separately. Use :meth:with_metadata to get a copy of a space with other metadata.

    Metadata is a description, not part of the data domain: __eq__, is_subspace and is_subspaceeq ignore it (use space_utils.metadata_utils.spaces_equal_with_metadata to compare it too). It is kept by to(), the batching utilities, serialization and the transformations that keep the meaning of the data, and dropped where the meaning is lost (e.g. flatten_space).

    The keys below form a shared vocabulary understood by UniEnv utilities (e.g. the video wrappers and unienv_data.storages.dict_storage_kwargs_from_space). None of them is required or enforced at construction, and any other keys (and kinds) are allowed. "Per element" lists have one entry per element of the space's last axis:

    • kind (str): what the data is. Recommended: "image", "depth", "segmentation", "normal", "pointcloud", "proprio", "action", "pose", "force", "tactile", "teleop", "keypoints", "mask", "intrinsics", "extrinsics", "privileged", "task" (goals / targets), "state".
    • format (str): pixel format of images, "rgb", "bgr", "rgba", "bgra" or "gray".
    • layout (str): axis order of the trailing image dims, "HWC", "CHW" or "HW" (single channel without a channel axis); leading dims are batch dims.
    • units (str, or per element list of str): physical units, e.g. "m", "mm", "rad", "rad/s", "m/s", "m/s^2", "N", "N*m", "A", "V", "degC", "px", "s"; "normalized" for unitless normalized data.
    • frame (str): reference frame, e.g. "world", "base", "camera_cv" (OpenCV: x right, y down, z forward), "camera_gl", "link_local", "wrist".
    • rotation (str): rotation representation inside a pose / action vector, "quat_wxyz", "quat_xyzw", "euler_<axes>" with transforms3d axes (s static / extrinsic, r rotating / intrinsic, e.g. "euler_sxyz", "euler_rxyz"), "rot6d", "matrix" or "axis_angle".
    • control (str, actions): what is commanded, e.g. "joint_position", "joint_velocity", "joint_torque", "eef_pose", "eef_velocity", "gripper".
    • mode (str, actions): "absolute", "delta" or "velocity".
    • normalized (bool): the values are normalized.
    • range ([low, high], scalars or per element lists): the physical range normalized values map to, when known.
    • names (per element list of str): e.g. joint names.
    • source (str): name of the camera / sensor producing the data.
    • fps (positive number): capture rate of the source.
    • label (str): human readable name.

    A vector packing several quantities (e.g. position 3 + quaternion 4 + gripper 1) is described per element with names and / or a units list, while rotation names the representation of its rotation part. space_utils.metadata_utils has builders for these keys (image_metadata, action_metadata, ...), annotate to attach metadata to nested spaces and validate_metadata to check it.

    is_subspaceeq ¶

    is_subspaceeq(other: Space) -> bool

    Return whether this space is a non-strict subspace of other (self ⊆ other).

    A space a is a non-strict subspace of b (a ⊆ b) when every valid sample of a is also a valid member of b; equality is allowed, i.e. a == b implies a.is_subspaceeq(b).

    The primary use case is a controller that declares its REQUIRED observation space and checks required.is_subspaceeq(env_observation_space): for DictSpace this must hold even when the environment space exposes EXTRA keys beyond the required ones (unlike DictSpace.contains, which demands exact key equality). Controller-required-space checks should typically use is_subspaceeq rather than the strict is_subspace because a controller's required space may exactly equal the env space.

    Comparison policy (structural only):

    • The two spaces must share the same backend type.
    • Dtypes must be strictly equal; no implicit cast widening is performed.
    • device is intentionally ignored — two spaces on different devices may still be in a subspace relation.

    Cross-type comparisons (e.g. BoxSpace vs DictSpace) return False rather than raising. Subclasses override this method to provide concrete structural containment checks; the base implementation raises NotImplementedError to mirror the abstract-method style of this class.

    is_subspace ¶

    is_subspace(other: Space) -> bool

    Return whether this space is a STRICT subspace of other (self ⊂ other).

    Defined uniformly for all spaces as::

    self.is_subspace(other)  ⟺  self.is_subspaceeq(other) and not other.is_subspaceeq(self)

    I.e. self ⊆ other holds but other ⊆ self does not, so self is a PROPER (strict) subspace of other. This is the ⊂ relation versus the non-strict ⊆ provided by :meth:is_subspaceeq.

    This definition is used instead of relying on __eq__ because some space classes only have identity __eq__; defining strict containment via the symmetric non-strict check works uniformly for all classes regardless of their __eq__ implementation.

    For structurally-distinct-but-mutually-containing spaces (which should not occur under the strict dtype/shape policies enforced by the per-class is_subspaceeq implementations) this degrades gracefully to False: if both self.is_subspaceeq(other) and other.is_subspaceeq(self) hold, the two spaces are considered equivalent and neither is a STRICT subspace of the other.

    If either side's is_subspaceeq is not implemented (the base :meth:is_subspaceeq raises NotImplementedError), the exception propagates to the caller — it is NOT swallowed into False so that callers can tell that the comparison is unsupported.

    Note: controller-required-space checks should typically use :meth:is_subspaceeq (a controller's required space may exactly equal the env space, in which case the strict is_subspace would return False).

    clip ¶

    clip(x: Any) -> SpaceDataT

    Project x onto this space and return the projected value.

    clip is defined on the TARGET (subset) space. Contract: if self.is_subspaceeq(source) holds, then for every x with source.contains(x)::

    self.contains(self.clip(x))

    unless no meaningful projection exists, in which case clip raises ValueError instead of inventing data (e.g. a required DictSpace key is missing, or a string / dynamic axis / graph is shorter or smaller than this space's minimum; each space documents its cases).

    Additionally:

    • clip is idempotent on members: self.clip(y) equals y whenever self.contains(y).
    • The input is never mutated; the result is new data, or x (or parts of it) itself where nothing needs to change.
    • The result follows this space's backend and dtype conventions (e.g. a BoxSpace casts to its dtype).

    Inputs that are not members of any superspace (wrong structure, wrong shape, ...) are not supported and may raise.

    The base implementation raises NotImplementedError to mirror the abstract-method style of this class; subclasses override it.

    is_subspace ¶

    is_subspace(other: Space) -> bool

    Return whether this space is a STRICT subspace of other (self ⊂ other).

    Defined uniformly for all spaces as::

    self.is_subspace(other)  ⟺  self.is_subspaceeq(other) and not other.is_subspaceeq(self)

    I.e. self ⊆ other holds but other ⊆ self does not, so self is a PROPER (strict) subspace of other. This is the ⊂ relation versus the non-strict ⊆ provided by :meth:is_subspaceeq.

    This definition is used instead of relying on __eq__ because some space classes only have identity __eq__; defining strict containment via the symmetric non-strict check works uniformly for all classes regardless of their __eq__ implementation.

    For structurally-distinct-but-mutually-containing spaces (which should not occur under the strict dtype/shape policies enforced by the per-class is_subspaceeq implementations) this degrades gracefully to False: if both self.is_subspaceeq(other) and other.is_subspaceeq(self) hold, the two spaces are considered equivalent and neither is a STRICT subspace of the other.

    If either side's is_subspaceeq is not implemented (the base :meth:is_subspaceeq raises NotImplementedError), the exception propagates to the caller — it is NOT swallowed into False so that callers can tell that the comparison is unsupported.

    clip ¶

    clip(x: GraphInstance[BArrayType]) -> GraphInstance[BArrayType]

    Project the (possibly batched) graph x onto this graph space (see Space.clip).

    • Graphs with more than max_nodes nodes keep their first max_nodes nodes; edges touching a dropped node are dropped too. Kept nodes keep their index, so the remaining edges stay valid.
    • Graphs with more than max_edges (remaining) edges keep their first max_edges edges, in order. The edge arrays are compacted per graph (dropped edges move into the padding).
    • Node / edge features are clamped with the feature spaces (padding included, as contains checks it); edge features are dropped if this space has no edge feature space.

    Every graph of a batch (batch_shape) is handled separately; the padded node / edge axes shrink to the largest remaining count. Returns a new GraphInstance; unchanged arrays are shared with x.

    Raises ValueError if x is not a GraphInstance of this batch shape, lacks node features or (for spaces with edges) edges, or if some graph has fewer than min_nodes nodes or, after dropping, fewer than min_edges edges (nodes and edges cannot be invented).

    is_subspaceeq ¶

    is_subspaceeq(other: Any) -> bool

    Return whether this graph space is a non-strict subspace of other (⊆).

    True iff other is a GraphSpace on the same backend, the node and edge feature spaces are subspaces recursively, and self's node/edge count ranges are contained within other's:

    • other.min_nodes <= self.min_nodes and self.max_nodes <= other.max_nodes (treating None as +∞);

    device is ignored.

    is_subspace ¶

    is_subspace(other: Space) -> bool

    Return whether this space is a STRICT subspace of other (self ⊂ other).

    Defined uniformly for all spaces as::

    self.is_subspace(other)  ⟺  self.is_subspaceeq(other) and not other.is_subspaceeq(self)

    I.e. self ⊆ other holds but other ⊆ self does not, so self is a PROPER (strict) subspace of other. This is the ⊂ relation versus the non-strict ⊆ provided by :meth:is_subspaceeq.

    This definition is used instead of relying on __eq__ because some space classes only have identity __eq__; defining strict containment via the symmetric non-strict check works uniformly for all classes regardless of their __eq__ implementation.

    For structurally-distinct-but-mutually-containing spaces (which should not occur under the strict dtype/shape policies enforced by the per-class is_subspaceeq implementations) this degrades gracefully to False: if both self.is_subspaceeq(other) and other.is_subspaceeq(self) hold, the two spaces are considered equivalent and neither is a STRICT subspace of the other.

    If either side's is_subspaceeq is not implemented (the base :meth:is_subspaceeq raises NotImplementedError), the exception propagates to the caller — it is NOT swallowed into False so that callers can tell that the comparison is unsupported.

    Note: controller-required-space checks should typically use :meth:is_subspaceeq (a controller's required space may exactly equal the env space, in which case the strict is_subspace would return False).

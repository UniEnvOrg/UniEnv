    Bases: BatchSampler[SamplerBatchT, SamplerArrayType, SamplerDeviceType, SamplerDtypeType, SamplerRNGType, BatchT, BArrayType, BDeviceType, BDtypeType, BRNGType]

    Run sampler's sample* functions (and epoch iteration over its get*_at functions) in n_workers background processes, keeping n_buffers batches queued.

    Workers pay off when producing a batch is expensive (decoding, transformations, storage reads). For data already in RAM (e.g. an in-memory ReplayBuffer), sampling in-process is usually faster (e.g. 0.7 ms vs 3 ms for 256 samples of 48 KiB with 4 workers): every batch is otherwise copied to the parent through shared memory. Workers run their torch ops single-threaded (see _limit_worker_intraop_threads).

    Parameters:

    Name Type Description Default
    shared_memory bool

    For sample() / sample_with_metadata() of samplers producing torch CPU tensors, workers copy each batch into one of n_buffers + 1 pre-allocated shared-memory slots and the parent copies it out, instead of sending every tensor through the result queue (a new shared-memory file and file descriptor per tensor and batch). This pays off when batches arrive at a high rate (e.g. ~2x for 64 samples of 48 KiB); for large batches the copy out of the slot in this process can cost more than it saves, so it is off by default.

    manual_seed(seed)

    Reseed the sampler. Running sample* workers (and the batches they already queued) are stopped: they restart on the next call with seeds drawn from the reseeded sampler, so that the batches that follow depend only on seed. Epoch iterations in progress keep their permutation.
